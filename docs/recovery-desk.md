# Recovery desk

The private operator desk defaults to unresolved obligations. Its server projection puts cases with persisted escalation first, then overdue obligations ordered by their original delivery deadline. Unpaid, processing and completed views expose other records without changing obligations. File expiry never settles an order.

Selected cases show canonical receipt, delivery, execution and disposition facts separately from model-selected tool observations. Action evidence and durable invocation deadlines remain visible across reloads. Late delivery is explicitly labeled. Operator access does not grant customer document downloads.

`RECOVERY_AGENT_URL` is the backend invocation base URL, including its existing path prefix. `RECOVERY_AGENT_SECRET` is a narrow service bearer token matching the backend's `AGENT_SERVICE_SECRET`. These are server-only web configuration. The web must never receive `OPENROUTER_API_KEY`, merchant, administrator or registrar signing keys. The POST operator endpoint requires an operator session and the configured same origin; it rejects upstream redirects and returns a fresh database projection rather than forwarding provider output.

The UI displays the persisted 12-call case allowance and 60-second invocation bound. Exhaustion prevents further model investigation; fresh deterministic checks and permitted actions remain available. Handlers remain authoritative. A browser/request timeout leaves the investigation history visible for refresh. Existing deterministic reconciliation and separately authorized refund obligations continue when model execution fails. Purchased retry uses the existing trusted conversion admission boundary; refund registration remains a separate scope.

## Guarded operator actions

The desk now offers fresh deterministic evidence checks, restoration of verified prepared output, and the individually permitted purchased retry. These controls remain available when the persisted model budget is exhausted. Every request derives its actor and session binding from the authenticated server session, records request-time canonical evidence, and dispatches only its durable request ID. The service rechecks configured operator identity, session validity, invocation deadline and action permission after admission locks. Existing conversion checks still establish whole-parent stopping, fresh final output evidence, retention, purchased policy and the original delivery deadline.

`OPERATOR_CONVERSION_URL` and `OPERATOR_CONVERSION_SECRET` are server-only web configuration. The separate secret authorizes the conversion service's `/operator` route; it does not authorize worker commands. Both backend services receive the configured public `OPERATOR_WALLET_ADDRESS`. The worker cannot select operator requests or sessions, and deterministic invocations cannot claim model calls or use worker HTTP tools. Operator model investigations use a narrow request-bound admission function and link audit completion to the actual invocation.

Private operator request history records actor, action, timestamps, request evidence and outcome evidence. Customer projections retain the canonical delivery/execution summaries. Session hashes, object keys and raw operator audit never appear there. Stale actions return an explanation and a refreshed canonical case. Transport failure after dispatch records uncertainty; it cannot establish that execution was skipped or stopped. A request timeout preserves durable completion, and late completion can finish its audit without resetting budget or clearing escalation. Existing automatic reconciliation remains authoritative.
