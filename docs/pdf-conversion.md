# Paid PDF conversion

A receipt-confirmed purchase invokes the authenticated `mendconversion6` Neon Function. Its durable generation-zero claim permits one initial parser per order. The original payment block timestamp establishes the purchased deadline; invoking or downloading does not reset it. Backend execution is deployed on Neon Free in Singapore; the web application receives only its URL and a service authentication secret.

The function explicitly overrides both injected database URLs and every injected storage credential with the conversion role. It receives no purchaser, registrar, administrator, session, or model credentials. A narrow recovery-worker authentication secret protects its inspect/output/restore endpoints. The PDF parser runs in a Node worker thread with an empty environment, receives bounded PDF bytes, and returns bounded plain text. PDF.js extracts local text without an external model or OCR provider.

The parent verifies the accepted upload hash, observes the parser's `exit` event, then records a durable output candidate before writing storage. It reads the stored object back and verifies nonempty content and its hash before recording authenticated availability as delivery. `orders.result` is an authenticated manifest, not a public storage URL. Its seven-day expiry starts at object creation (`LastModified`), independently of the upload's creation clock. Result retrieval checks paying-wallet ownership, expiry, and the actual private bytes before serving an attachment.

Delivery records when verified bytes became available. `result_downloads` records a separately authenticated response served; it does not prove that a customer saved or read the file. Downloads and fixture restoration preserve the original expiry. Customer projections omit object keys and raw diagnostics.

## Deployment and checks

For initial provisioning, `scripts/deploy-conversion.mjs` requires an explicitly enrolled `CONVERSION_FUNCTION_SLUG` and durable `CONVERSION_SERVICE_ENV`, with reviewed conversion-role database/storage inputs. Do not run an old implicit-destination or secret-generation recipe. For an existing service whose original bindings are write-only, use the reviewed `scripts/deploy-release.mjs conversion` build-only path and its guarded `--deploy` mode; this preserves old bindings by omission and accepts only the new narrow web aliases. See [release identity and schema receipts](release.md#deployment-identity-and-order). Management credentials and conversion-role database/storage credentials never belong in the web environment.

Run `TEST_BASE_URL=http://127.0.0.1:3028 TEST_AUTH_ORIGIN=http://127.0.0.1:3028 PAYMENT_TEST_PURCHASER_ENV=/absolute/private/purchaser.env npx playwright test tests/conversion.spec.ts`. Cached signatures and private capabilities stay outside git. Optional `CONVERSION_FIXTURE_DB_ENV` enables local administrative setup for exact-expiry and controlled integrity-failure checks; those credentials are neither web nor function runtime configuration.

## Recovery boundary

`execution_attempts.stopped_at`, `stop_reason`, and `parser_exit_code` describe the parser only. They do **not** establish whole-execution termination, output absence, or refund safety: publication follows parser exit. A prepared output candidate may exist even if its order manifest was never committed. Later recovery must inspect that candidate and establish a shared disposition/publication fence before retry or refund. Scheduled interruption recovery now inspects whole-execution termination and prepared private outputs, requests a bounded stop when needed, and retains unknown outcomes for later observation. Valid prepared output can be restored through the shared publication fence. The single purchased retry and final refund arbitration now use durable eligibility, whole-execution stopping/output checks and shared disposition fences. The registrar independently revalidates the original payer/amount and failure evidence before authorizing repayment; ambiguous evidence remains unresolved. See [interruption recovery](evidence/issue-6.md) and [agent recovery](ticket7-runtime-proof.md).
