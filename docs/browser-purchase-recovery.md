# Browser purchase recovery decision

Before payment integration: use an origin-local IndexedDB journal and Web Locks for cross-tab exclusion. Commit each submission identity (random capability, idempotency key, hash and byte size), immutable returned terms and order ID before progressing. Persist the exact x402 signed header and read it back before its first transmission. Replays send that header unchanged; a pending attempt never offers another signature. Block upload/payment if durable storage or exclusive locks are unavailable. PDF bytes are held only in memory, never persisted.

Journal records are private bearer capabilities and signed spending authorizations. They are accessible to scripts on this origin and browser-profile users; this is not protection from XSS or local compromise. Require authenticated original-payer SIWE before reading or displaying records; hide records and filenames immediately when identity changes. Retain journal records to support uncertain settlement; never silently replace/delete pending authorization. Origin isolation is intentional; there is no export or user-managed state file.

After reload an unsigned draft can resume with the identical reselected PDF (hash/size checked), or its accepted order can proceed after sign-in. Rejected signing leaves the same unsigned order. A wallet without typed-data signing cannot start payment; an already signed attempt can be checked without another signature. An expired authorization or failed response stays recoverable with the original authorization and server evidence, never a blind replacement.

Cleared storage, private browsing eviction, another device or origin cannot recover this journal. SIWE original-payer lookup recovers owned/confirmed server orders. It cannot prove that every unconfirmed submission was absent. Show explicit guidance to inspect My orders and obtain operator help for uncertain payment; do not offer a replacement as recovery. Browser storage cannot guarantee survival against explicit clearing or OS eviction, and the UI discloses this limitation before upload. Persistent-storage permission is requested where supported; successful committed IndexedDB writes and read-back are mandatory regardless of that optional permission.
